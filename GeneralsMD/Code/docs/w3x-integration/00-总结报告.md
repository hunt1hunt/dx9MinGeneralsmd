# W3X 集成方案 — 总结报告

## 一、问题起源

在 PBR 渲染管线中，W3D 格式模型的法线贴图无法生效。经调研，根本原因是 W3D 格式缺乏切线/双切线数据，导致像素着色器无法将法线贴图从切线空间转换到世界空间。

## 二、调研结论

### 2.1 W3D 格式对切线的原生支持

W3D 格式规范（OpenSAGE 文档 + max2w3d 源码证实）存在以下切线相关块：

| Chunk ID | 名称 | 说明 |
|----------|------|------|
| `0x60` | `W3D_CHUNK_TANGENTS` | 每顶点切线向量数组（Vector3 × 12字节） |
| `0x61` | `W3D_CHUNK_BINORMALS` | 每顶点双切线向量数组（Vector3 × 12字节） |
| `0x00000020` | `W3D_VERTEX_CHANNEL_TANGENT` | VertexChannels 位掩码 |
| `0x00000040` | `W3D_VERTEX_CHANNEL_BINORMAL` | VertexChannels 位掩码 |

但我们的 `w3d_file.h` **缺失以上全部定义**。

### 2.2 max2w3d 导出器

- jonwil 在 2013 年为 max2w3d.dle 增加了切线/双切线导出功能
- 通过 UI 复选框控制（MikkTSpace 开关）
- 导出的文件写入 `0x60/0x61` 块（标准 W3D 格式）
- **W3D 和 W3X 共享同一份网格导出代码**（w3dexport.cpp），以 `#ifdef W3X` 区分序列化格式

### 2.3 max2w3d 源码仓库结构

```
w3dhub/max2w3d (v1.9.0)
├── w3dmaxtools/Source/w3dexport.cpp  ← 266KB 共享网格导出引擎
├── w3dmaxtools/Redist/w3dexport.h    ← W3DExportSettings（含 MikkTSpace）
├── scripts/w3d.h                     ← 格式定义（含 TANGENTS/BINORMALS）
└── w3xmaxtools/                      ← W3X 特有代码（XMLWriter + pugixml）
```

### 2.4 W3X 格式特性

- W3X 是 **XML 格式**（非二进制），存储完整的网格数据
- W3X **原生包含切线/双切线数据**（每个子网格均有 `<Tangents>` 和 `<Binormals>` 节点）
- W3X 通过 `<FXShader>` 节点引用 `.fx` 着色器文件，包含完整的 `<Constants>` 参数列表
- W3X 配备纹理声明 XML 体系（`<Texture id="..." File="...dds" OutputFormat="DXT5"/>`）

## 三、架构设计

### 3.1 双格式共存架构

```
资产加载前端
    │
    ├── .w3d ──→ W3D 读取路径（现有代码扩展）
    │              ├── 读取顶点/法线/UV/切线(0x60/0x61)
    │              ├── 无切线时运行时计算（Lengyel / MikkTSpace）
    │              ├── 材质参数来源：PBROverride.ini + _pbr.dds + _n.dds
    │              └── 渲染：使用我们自己的内联 PBR 着色器
    │
    ├── .w3x ──→ W3X 读取路径（新增）
    │              ├── 解析 XML → 读取顶点/法线/UV/切线/Triangles
    │              ├── 解析 FXShader 节点 → 获取 .fx 文件引用 + Constants
    │              ├── 加载对应的 .fx 文件（D3DXCreateEffect）
    │              ├── 纹理 ID → XML → DDS 路径解析
    │              └── 渲染：使用 RA3 原生 PBR 着色器（D3DXEffect 渲染）
    │
    └── 两者共享的 MeshModelClass 内存表示
              │
              ▼
        统一的场景管理（场景树 + HLod + 骨骼动画）
```

### 3.2 核心原则

1. **W3D 路径不改渲染方式**——继续用内联 PBR 着色器，只增加切线数据
2. **W3X 路径用 RA3 原生着色器**——D3DXCreateEffect 加载 .fx，不重写着色器
3. **两条路径独立渲染，共享场景**——可以在同一个战场里同时显示 W3D 和 W3X 模型
4. **条件状态映射**——RA3 的 ModelConditionState 映射到 Generals 的 ConditionState
