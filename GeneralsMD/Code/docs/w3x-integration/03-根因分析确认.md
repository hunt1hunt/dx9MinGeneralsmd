# W3X 模型渲染 — 根因分析确认记录

**日期**：2026-08-01
**状态**：W3X 管线全部打通，Humvee（APATAVGATTTANK_SKN）已能渲染出红色诊断模型，正在切换真实 RA3 shader。

---

## 一、问题现象

Humvee（悍马车，使用 W3X 模型 `APATAVGATTTANK_SKN`）**从未显示出来**。调试日志（DebugLogFileI.txt）显示：
- 模型加载成功（8 个子网格、18 根骨骼、贴图正常）
- `W3XRenderObj added to scene`（渲染对象已加入场景）
- 但**没有任何 Render 调用**（无 GetEffect、无渲染输出）
- 进入遭遇战时崩溃跳出

## 二、根因分析（已确认）

### 根因 1：W3XRenderObjClass 内存池未注册 → 崩溃

**现象**：进入遭遇战游戏崩溃，日志：
```
ASSERTION FAILURE: Initial size for pool W3XRenderObjClass not found
-- you should add it to MemoryInit.cpp
```

**原因**：`W3XRenderObjClass` 类声明中使用了内存池宏 `W3DMPO_GLUE(W3XRenderObjClass)`（W3XRenderObj.h:49）。该宏在首次实例化时调用 `createW3DMemPool("W3XRenderObjClass", sizeof(...))`，它会到 `MemoryInit.cpp` 的内存池注册表查找预创建的池。**表里没有该条目** → 池不存在 → 断言崩溃。

**修复**：`GameEngine/Source/Common/System/MemoryInit.cpp` 加入：
```cpp
{ "W3XRenderObjClass", 128, 32 },   // 紧跟 { "W3XModelDraw", 16, 16 } 之后
```

**重要**：MemoryInit.cpp 属于 **GameEngine** 项目，修复后必须 **Rebuild All**（不能只编译 GameEngineDevice）。

### 根因 2：包围球未变换到世界空间 → 永远被视锥剔除 → 从未渲染

**现象**：崩溃修复后不再崩溃，模型正常加载并加入场景，但**依然不可见**，且日志中没有任何 Render 调用（无 GetEffect/DIAG/Rendered）。

**原因**：`W3XRenderObjClass::Update_Cached_Bounding_Volumes()` 中包围球中心被固定在 `(0,0,0)`，**没有用 `Get_Transform()` 变换到世界空间**。

场景渲染流程（`WW3D2/scene.cpp` SimpleSceneClass::Customized_Render）：
```cpp
if (robj->Is_Really_Visible()) {   // ← 不满足就跳过，不调用 Render()
    robj->Render(rinfo);
}
```
而 `Is_Really_Visible()` 依赖 `Visibility_Check`（视锥剔除）设置的 `IS_REALLY_VISIBLE` 位：
```cpp
robj->Set_Visible(!camera->Cull_Sphere(robj->Get_Bounding_Sphere()));
```

由于包围球中心固定在原点 `(0,0,0)`，而相机在看地图其他位置 → 球永远在视锥外 → **永远被剔除** → `Is_Really_Visible()` 永远为 false → **Render() 永不调用 → 模型从未显示**。

**对照**：正常的 `MeshClass::Update_Cached_Bounding_Volumes()` 会把中心变换到世界空间：
```cpp
Get_Obj_Space_Bounding_Sphere(CachedBoundingSphere);
CachedBoundingSphere.Center = Get_Transform() * CachedBoundingSphere.Center;  // ← 关键
```

**修复**：`W3XRenderObj.cpp` Update_Cached_Bounding_Volumes 加入世界空间变换：
```cpp
Get_Transform().mulVector3(center);   // 与 MeshClass 一致
```

**验证**：修复后模型立即以红色（w3x_diag.fx 诊断 shader）显示。DIAG 日志确认视图矩阵正确：
```
DIAG view[3]=-2076.84,-430.00,18.91,1.00   ← 真实相机坐标（不再是单位矩阵）
```

## 三、其他已确认要点

| 项 | 结论 |
|----|------|
| 视图矩阵 | 旧构建用 `DX8Wrapper::Get_Transform(D3DTS_VIEW)` 返回单位矩阵（draw-module 上下文）；改用 `rinfo.Camera.Get_View_Matrix()` 正确 |
| WVP 转置约定 | `world^T·view^T·proj^T` 匹配 `DX8Wrapper::Set_Transform`（内部 transpose）；`Get_D3D_Projection_Matrix` 返回 SAGE 约定需 transpose |
| 诊断 shader | `w3x_diag.fx` 必须存在于游戏根目录（GetEffect 加载失败→Render 返回→不可见） |
| 诊断 shader 选中逻辑 | 仅当子网格有非 `defaultw3d.fx` 的 shader 才触发（W3XModelDraw.cpp 条件） |
| DSP 修复 | GameEngineDevice.dsp 曾有多余 `# End Source File` 导致新文件不被编译（3 处已修，223 Begin=223 End 平衡） |

## 四、真实 RA3 shader 切换（进行中）

- W3X 数据引用裸 shader 名（`objectssoviet.fx`、`objectsalliedtread.fx` 等）
- 真实 .fx 文件在游戏目录 `Shaders\RA3\`
- 需前缀路径：`outData.fxShaderName = "Shaders\\RA3\\"; outData.fxShaderName.concat(meshData.fxShaderName);`
- AsciiString 用 `.concat()` 拼接（无 operator+=）
