## 一、用户新假设（本窗口核心）

"模型用了太阳光照，但地表用了辅助光照，这两种光照的角度是不同的。"

→ 已确认机制：**地表 PBR 与模型光照确实来自两张独立的 INI 表**：

| 链路 | 数据源 | 光方向 |
|------|--------|--------|
| **模型/场景**（D3D 方向光） | `m_terrainObjectsLighting[tod][0].lightPos` | 光传播 +Z = lightPos（W3DDisplay.cpp:2178-2180 `mtx.Set(... lightPos ...)`，不取反）；光线射线 = `-Get_Z_Vector()`（doTheLight BaseHeightMap.cpp:565-572） |
| **地表 PBR c0** | `m_terrainLighting[tod][0].lightPos`（经 `m_terrainLightPos[0]`） | `c0 = -m_terrainLightPos[0]`（HeightMap.cpp:2114） |

- `GlobalData::setTimeOfDay`（GlobalData.cpp:1225）：`m_terrainLightPos[i] = m_terrainLighting[tod][i].lightPos`（**TerrainLighting*** 表）
- `W3DDisplay::setTimeOfDay`（W3DDisplay.cpp:2170-2180）：D3D 方向光 +Z = `m_terrainObjectsLighting[tod][i].lightPos`（**TerrainObjectsLighting*** 表）
- 两张表在 GlobalData.cpp:235-281 各自独立 parse，默认都 (0,0,-1)，但游戏数据里角度**可以不同**。
- W3X 模型 PBR（W3XEffectManager.cpp:532/640/730、W3DScene.cpp:840）也统一用 `-m_terrainLightPos[0]`。

## 六、2026-08-17 收尾：两表光照假设已证伪 + 法线可视化工具

### 1. "太阳光 vs 辅助光角度不同"假设 = **已证伪**

`E:\sun_dir.log`（旧版 one-shot 诊断，抓到的是 init 期默认值）里最有价值的一行是**直接读 INI 表**的：
```
L0  terrainLighting.lightPos=(-0.810,0.380,-0.450)
L0  objectsLighting.lightPos=(-0.810,0.380,-0.450)   ← 两表完全相同
```
结合 `HT_PBR_RENDER: sunDir=(0.809,-0.379,0.449)`（= `-m_terrainLightPos[0]` 渲染期真实值）：
- 地表 PBR c0 = `-m_terrainLightPos[0]` = (0.809,-0.379,0.449)
- 模型光线 = `-m_myLight[0].Z` = `-objectsLighting.lightPos` = 同一个方向
- 参考光照 `getStaticDiffuse`（BaseHeightMap.cpp:2090，旧版正确地形光照）也是 `dot(-m_terrainLightPos, heightmapNormal)`，平地 dot = 0.449 > 0 正常受光
- **→ 地表与模型光照方向完全一致，反装不在光照，在法线管线。**

### 2. 法线管线数学核对（都在纸面上正确，所以需要可视化实证）

- `geoN = normalize(cross(B,T))`，其中 T ∝ ∂P/∂u ≈ +X、B ∝ ∂P/∂v ≈ -Y（引擎 V ∝ -Y，WorldHeightMap getUVForTileIndex）。cross(B,T) = (+X)×(-Y) = **+Z=UP，与高度图参考法线 l2r×n2f 一致**，平地 dot(geoN,c0)=0.449 与旧版相同。
- 凹凸 `N = normalize(geoN + (nm.x*T*c2.z + nm.y*B*c2.w)*conc*geoN.z)`，`conc = c2.x*(1-diffuse.a)`（vertex alpha=贴图混合权重，只有 alpha<255 的过渡区才生效）。
- 方向全对，凹凸符号翻转过也无效 → **剩下的可能：bump 仍反装 或 运行态与源码不一致。必须用可视化一锤定音。**

### 4. 实证结论（已完成，bump 反装实锤 + 修复）

1. `SUN_DIR_END`（真实值）：L0/L1/L2 的 `modelRay` 与 `terrainPBR.c0` **逐字相同**（如 L0 都是 (0.810,-0.380,0.450)）。光照一致 → 反装在法线管线。✅ 光照假设证伪坐实。
2. `E:\nm_diag.txt`=`1`（geoN）：平地/顶面紫色 (0.5,0.5,1)=geoN up → **geoN 正确**；山坡偏白。
3. `E:\nm_diag.txt`=`2`（混合 N）：**反侧偏紫红** → 凹凸项把法线推向与 geoN 相反方向 → **bump 反装实锤**。
4. **根因（2026-08-17 确定）**：屏幕导数 T/B 的 UV→屏幕雅可比 det<0 时，T、B **同时取反**，而 `geoN=cross(B,T)` 对 det 不敏感（保持 up），`bump=nx*T+ny*B` 对 det 敏感 → 凹凸整体镜像。**之前"凹凸符号翻转无效"很可能是构建配置陷阱（改进了 RTSI.exe，游戏跑 RTS.exe）造成的 stale 二进制。**
5. **修复**：`s_terrainBumpSignX = -1.0f`、`s_terrainBumpSignY = -1.0f`（W3DShaderManager.cpp:2514-2515）。
